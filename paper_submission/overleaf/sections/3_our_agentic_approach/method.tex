
AutoModel Advisor splits model selection across two cooperating agents, coordinated by an \textbf{orchestrator} that routes work between them, retries failed steps, and decides when to stop. Retrieval predicts what is promising; evaluation proves it on the user's own data.

\paragraph{Retrieval Agent: making a cold-start dataset scorable.}
A brand-new dataset is a node with no edges, so no graph method can score it directly. Both of our retrieval strategies share the same first two steps: an LLM produces a structured summary of the dataset (task, domain, size, format), and the summary is embedded with a text embedding model. The strategies then diverge in how they use ArtifactLinker's graph:

\begin{itemize}
\item \textbf{Approach 1 -- cosine retrieval.} We compute cosine similarity between the new dataset's summary embedding and the embeddings of every dataset already in ArtifactLinker's graph, retrieving its top-$K$ most similar neighbors. This induces a neighborhood for the cold-start dataset: the models measured on those similar datasets, together with their scores, are assembled into graph-conditioned evidence and handed to an LLM, which reasons over that evidence to recommend models. This is our own dataset-similarity retrieval method, inspired by the graph-learning reframing of TransferGraph \citep{li2024transfergraph}, rather than an integration of TransferGraph's trained regressor itself.
\item \textbf{Approach 2 -- direct GNN scoring.} Instead of borrowing a neighborhood, we insert the new dataset as a new node directly into ArtifactLinker's graph (using its summary embedding as the node feature) and query the trained joint GNN's link $\times$ attribute score for every candidate model. Because the dataset was never seen during training, this exercises ArtifactLinker's inductive setting: the GNN must score a node it has never observed.
\end{itemize}

Both approaches are constraint-aware: candidates that violate the user's stated constraints (e.g., parameter budget) are filtered before ranking. The retrieval LLM receives two distinct evidence blocks -- ArtifactLinker (GNN) context and dataset-similarity context -- as separate, labeled sources, so its recommendation can be traced back to which evidence supported which pick.

\paragraph{Evaluation Agent: measuring performance de facto.}
The retrieval shortlist is a prediction, not a fact. The Evaluation Agent takes the candidate models and the user's dataset, plans an evaluation, writes and runs the evaluation code, handles execution errors and retries, and records the measured score for each candidate -- the same verify step ArtifactLinker applies to its own top-ranked links, now applied to our retrieval agent's cold-start shortlist.

\paragraph{Closed-loop refinement.}
After evaluation, the orchestrator does not stop: it analyzes where each candidate fails (which classes, slices, or examples it gets wrong) and feeds that error analysis back to the Retrieval Agent as additional context for the next round. Each round targets the previous round's failures, so model selection becomes iterative experimentation that improves itself rather than a single blind pass. Concretely, an initial retrieval round produces a ranked shortlist; the Evaluation Agent measures it on the user's data; a revision round re-prompts the retrieval LLM with the original evidence, the round-1 recommendation, and the round-2 measured results and error notes, letting it confirm, drop, or replace candidates based on what actually happened rather than re-predicting from the graph alone.
